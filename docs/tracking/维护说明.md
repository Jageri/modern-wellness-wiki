# 内容与复审维护

本页负责条目登记、复审周期、工程验证和交付流程。内容格式、医学审计与评级要求见[文档分工](../README.md)。

## 新增或修改条目

1. 依据相应撰写和审计规范完成中英文正文及核验记录。
2. 同步 `INDEX.md`，在 `docs/tracking/entries.json` 登记稳定 ID 与两种语言路径。改题名或路径不换 ID，新增条目使用新的唯一 ID；百分号按 URL 编码，`+` 保留原字符含义。
3. 完成审计后登记 `status: reviewed`、真实 `evidenceReviewedOn`、对应 `audit` 路径、审阅者及 `reviewerType`。AI 审阅填 `ai`，不得冒充医学专家署名复核；内容维护责任归仓库维护者。
4. 引用整理、工程修复或单项证据补充登记在 `updates`，写明中英文范围、日期与审计路径。局部修改不重置整条的基础证据复审日期和期限。
5. 运行验证，处理失败，再按任务授权提交、推送或发布；只纳入本轮相关文件，并让双语内容、审计记录、索引与清单保持同批一致。不能按条目数量自动推送，也不使用 `git add -A` 混入其他未完成工作。交接写明实际达到的状态。

网页分别显示 Git 页面更新时间、基础证据复审与局部更新。清单日期须来自对应审计记录；不能把文案调整时间当作证据检索完成时间。

## 复审安排

- 新条目发布前完成审计；重要新证据、勘误或撤稿可能改变结论时及时复审。
- 已有条目按季度复审，`nextReviewDue` 不晚于基础证据复审日期后三个日历月；目标月份没有同一日时取月末。
- 逾期需完成实际复审并留下记录，不能只改日期消除报错。自动检查的警告或失败不等同于医学结论。

## 安装与验证

运行环境要求、命令定义和依赖版本分别以 `package.json`、`package-lock.json` 为准；CI 触发条件和权限以 `.github/workflows/` 为准。使用符合环境要求的 Node.js 后执行 `npm ci`。

| 命令 | 用途 |
| --- | --- |
| `npm test` | 验证内容检查器对错误输入的处理 |
| `npm run content:check` | 核对清单、结构、双语 PMID 集合、引用标记、索引、文档链接和审计记录；逾期警告 |
| `npm run content:reviews` | 同上，并把复审逾期作为失败 |
| `npm run docs:build` | 从源 Markdown 生成站点，不回写百科源文件 |
| `npm run docs:check` | 检查构建后的页面、语言配对、SEO、复审日期与脚注 |
| `npm run check` | 运行提交前的完整验证链 |
| `npm audit` | 检查当前安装树的依赖安全公告 |

条目数量与网页配对从清单生成，不在文档或检查器中另设固定总数。自动验证只确认结构和记录存在，不保证语义、数据或医学建议正确。

## 依赖维护

`overrides.vite` 用于处理构建依赖链的安全问题，`markdown-it-footnote` 负责脚注渲染。升级时检查 override 是否仍需要，并完成构建、站点检查与依赖审计；具体版本不在本页另记一份。
